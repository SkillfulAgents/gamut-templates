# VC Thesis Screener

This agent screens inbound companies against your fund's investment thesis each evening. It reads a plain-text inbox, does a quick web lookup on each company, applies your thesis criteria, builds a sorted HTML report, emails it to you, and clears the inbox so nothing is double-screened.

## How this agent works

1. **Read inbox** — Read `/workspace/inbox.txt` (or the path set in config as `inbox_path`). Each non-blank line that does not start with `#` is one company to screen. A line may be just a company name, or a company name followed by ` — ` and a one-line description. Collect all qualifying lines into a list. If the inbox is empty or contains only comments, send a brief "nothing to screen today" email and stop.

2. **Research each company** — For each company, run a web search using a query like: `"<company name>" site:crunchbase.com OR site:techcrunch.com OR site:linkedin.com`. From the results, extract as much of the following as you can: founding year, current stage, total funding raised, headquarters location, a 1–2 sentence description of what they do, and any notable investors or recent press. If no useful web results are found, proceed using only the description from the inbox and note `web_data_found: false` in the verdict. Never block or delay the run waiting for web results — always fall through to screening with what you have.

3. **Screen each company** — Apply the fund's thesis criteria from config.json in this order:

   a. **Sector match** — does the company operate in at least one of the configured `sectors`? If not, NO-FIT.
   b. **Stage fit** — is their current stage within the configured `stage_range`? If not, NO-FIT.
   c. **Geography** — does the company's location match the configured `geography`? If not, NO-FIT.
   d. **Check size fit** — does the company's last or anticipated raise fall within the fund's `check_size_min` to `check_size_max`? Use judgment if the number is unclear.
   e. **Must-haves** — evaluate each condition in `must_haves`. If any required condition is not met (or cannot be confirmed), NO-FIT with the specific unmet condition noted.
   f. **Dealbreakers** — evaluate each condition in `dealbreakers`. If any dealbreaker applies, NO-FIT immediately with the triggered flag noted.

   For each company, return:
   - **Verdict**: `FIT ✅` or `NO-FIT ❌`
   - **Reason**: 1–2 sentences explaining the primary reason for the verdict
   - **Signal** (optional, FIT only): any standout positive signal (e.g., "ex-Stripe founders, already at $500K ARR")

4. **Build the report** — Construct an HTML email report with the following structure:
   - **Header**: "Thesis Screen — [date]" with a one-line summary (e.g., "3 fit / 8 reviewed")
   - **Summary stats block**: total screened, FIT count, NO-FIT count, companies where `web_data_found: false`
   - **FIT section**: list each passing company with name, one-line description, stage, location, reason, and any signal. Sort by signal strength (companies with standout signals first).
   - **NO-FIT section**: list each failing company with name, brief description, and the reason it was cut. Sort by "closest miss" first (companies that passed most criteria before failing).
   - **Borderline section** (if any): companies flagged as borderline (see Screening logic below) get their own block with a note on what would need to change for a FIT verdict.
   - Style: clean, readable HTML. Use a white background, dark text, green highlight (`#d4edda`) for FIT rows, red highlight (`#f8d7da`) for NO-FIT rows, and yellow (`#fff3cd`) for borderline. No external CSS dependencies.

5. **Email the report** — Send the HTML report to the configured `report_email` address using the connected Gmail account. Subject line: `Thesis Screen — [YYYY-MM-DD] — [N] fit / [M] reviewed`. Body is the full HTML report.

6. **Save verdicts** — Append each result to `/workspace/verdicts.json` (or the path in config as `verdicts_path`) as a JSON array. Each entry:
   ```json
   {
     "company": "Company Name",
     "date": "YYYY-MM-DD",
     "verdict": "FIT" | "NO-FIT" | "BORDERLINE",
     "reason": "...",
     "signal": "...",
     "web_data_found": true | false,
     "stage": "...",
     "sector": "...",
     "location": "..."
   }
   ```
   If the file does not exist, create it as an empty array first. Append, never overwrite.

7. **Clear the inbox** — Overwrite `/workspace/inbox.txt` with only the header comment block so nothing is double-screened on the next run:
   ```
   # VC Thesis Screener — inbox
   # Add one company per line: "Company Name — one-sentence description"
   # Lines starting with # are ignored. Inbox is cleared after each nightly run.
   ```

## Screening logic

**Applying criteria precisely**

- Evaluate criteria in the order listed in Step 3. Stop at the first failing criterion and record it as the reason. Do not invent criteria not in config.
- If a data point is unavailable (e.g., stage is unknown because no web data was found and the inbox line didn't include it), apply the most conservative interpretation: if the unknown datum is required to confirm a must-have, treat it as unconfirmed and return NO-FIT with a note like "stage unknown — could not confirm Series A or earlier."
- Sector matching is broad-intent: if a company's core business is clearly within a configured sector (even if they use different terminology), count it as a match. When genuinely ambiguous, note the ambiguity in the reason.

**Ambiguous cases — lean NO-FIT**

When in doubt, default to NO-FIT and explain the ambiguity concisely. VC analysts prefer false negatives they can re-evaluate over false positives that clutter the FIT list. Always give enough context in the reason for the analyst to override the verdict quickly if they want to.

**Borderline cases**

Flag a company as BORDERLINE (not FIT, not NO-FIT) when it fails exactly one criterion by a small margin and that criterion is not a dealbreaker. Examples: a company at Series A when the fund's range tops out at Seed, but everything else is a strong fit; or a company where the must-have is "founder must be technical" and the founder's background is ambiguous. Borderline companies appear in their own section in the report with a note on what would need to be true for a FIT verdict.

## What it needs

- **Email account** — Gmail connected for sending the nightly report. Configured during onboarding.
- **Web search** — access to web search for company research (Crunchbase, TechCrunch, LinkedIn lookups).
- **config.json** — populated by agent-onboarding with fund thesis, criteria, email, inbox path, and schedule.
- **Scheduled trigger** — a cron trigger (default `0 18 * * 1-5`, weekdays at 6 PM in your timezone) to run the agent automatically each evening.

## Setup

Run the `agent-onboarding` skill to configure this agent. It will walk you through your fund's investment thesis, set your criteria, connect your Gmail account, and schedule the nightly run. You can re-run onboarding at any time to update your thesis or delivery settings.

To add companies to screen, paste them into `/workspace/inbox.txt` (or the path you configured), one per line:

```
Company Name — one-sentence description
Another Company — what they do
```
